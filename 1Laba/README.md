## Теоретическая часть (кратко)

### Файловые дескрипторы (FD)

В UNIX-подобных ОС доступ к ресурсам (файлы, сокеты, каналы, устройства) осуществляется через **файловые дескрипторы** — неотрицательные целые числа, индексирующие таблицу дескрипторов процесса. Каждый процесс при запуске получает три стандартных дескриптора:

| FD | Макрос | Назначение |
|---|---|---|
| 0 | `STDIN_FILENO` | Стандартный ввод |
| 1 | `STDOUT_FILENO` | Стандартный вывод |
| 2 | `STDERR_FILENO` | Стандартный вывод ошибок |

Поэтому **первый созданный сокет обычно получает номер 3**.

### Сокеты: TCP vs UDP

| Характеристика | TCP (`SOCK_STREAM`) | UDP (`SOCK_DGRAM`) |
|---|---|---|
| Соединение | Ориентирован на соединение | Без соединения |
| Надёжность | Гарантированная доставка | Нет гарантий |
| Границы сообщений | Поток байтов | Датаграммы |
| Примеры | HTTP, SSH, FTP | DNS, DHCP, игры |

### Сетевой порядок байт

x86 и ARM — Little-Endian, а сетевой протокол (RFC) требует **Big-Endian**. Без преобразования порт `8080 = 0x1F90` будет прочитан как `0x901F = 36895`. Поэтому обязательны:

- `htons()` / `htonl()` — host → network
- `ntohs()` / `ntohl()` — network → host

### Структура `sockaddr_in`

```c
struct sockaddr_in {
    short          sin_family;  // AF_INET
    unsigned short sin_port;    // порт в сетевом порядке байт
    struct in_addr sin_addr;    // IP-адрес (32 бита)
    char           sin_zero[8]; // выравнивание
};
```

## Ответы на контрольные вопросы

**1. Что такое файловый дескриптор? Какие стандартные дескрипторы существуют?**  
FD — целое неотрицательное число, индексирующее таблицу открытых ресурсов процесса. Стандартные: `0` (stdin), `1` (stdout), `2` (stderr).

**2. Почему первый созданный сокет обычно получает дескриптор 3?**  
Потому что FD `0–2` уже заняты стандартными потоками при запуске процесса. Ядро выделяет минимальный свободный номер — им оказывается `3`.

**3. Что такое сокет? Из чего он состоит?**  
Сокет — программный endpoint для обмена данными. Идентифицируется парой `(IP-адрес, порт)`.

**4. Зачем нужны `htons()` и `htonl()`? Что произойдёт, если забыть преобразование?**  
Преобразуют порядок байт из host (Little-Endian на x86) в network (Big-Endian). Без них порт `8080 = 0x1F90` будет прочитан как `0x901F = 36895` — соединение уйдёт «не туда».

**5. В чём разница между `inet_pton()` и `inet_addr()`? Почему `inet_pton()` предпочтительнее?**  
`inet_pton()` поддерживает IPv6, возвращает чёткий код (`1` успех, `0` неверный формат, `-1` ошибка). `inet_addr()` возвращает `INADDR_NONE` (`0xFFFFFFFF`), который совпадает с валидным адресом `255.255.255.255`, и не поддерживает IPv6.

**6. Какие параметры принимает `socket()`? Что означает `protocol = 0`?**  
`domain` (семейство), `type` (тип), `protocol`. `protocol = 0` — автовыбор: TCP для `SOCK_STREAM`, UDP для `SOCK_DGRAM`.

**7. Для чего нужен `bind()`? Что такое `INADDR_ANY`?**  
`bind()` привязывает локальный адрес и порт к сокету. `INADDR_ANY` (`0.0.0.0`) — «слушать на всех интерфейсах машины».

**8. Как обрабатывать ошибки системных вызовов? Что выводит `perror()`?**  
Проверять возврат `< 0`, вызывать `perror("имя_вызова")`. `perror()` печатает в stderr строку вида `"имя_вызова: strerror(errno)"`.

**9. Что означает ошибка `EADDRINUSE`? Как её обработать?**  
Порт уже занят другим процессом. Решение: выбрать другой порт, использовать `SO_REUSEADDR`, или остановить занявший процесс.

**10. Почему сокет считается файлом? Какие аналогии между `open/read/write/close` и `socket/recv/send/close`?**  
В UNIX «всё есть файл»: сокет — тоже FD в таблице процесса. Соответствия: `open ↔ socket`, `read ↔ recv`, `write ↔ send`, `close ↔ close`. Ядро работает с сокетом через тот же механизм дескрипторов.

**11. Что такое сетевой порядок байт? Почему он Big-Endian?**  
Порядок байт, зафиксированный в RFC для передачи по сети. Big-Endian выбран, чтобы машины с разной архитектурой (x86 — LE, PowerPC — BE) понимали друг друга одинаково.

**12. Как преобразовать IP-адрес из текстового в бинарный и обратно?**  
Текст → бинарь: `inet_pton(AF_INET, "1.2.3.4", &addr)`. Бинарь → текст: `inet_ntop(AF_INET, &addr, buf, len)`.

**13. Какие семейства адресов и типы сокетов вы знаете?**  
Семейства: `AF_INET` (IPv4), `AF_INET6` (IPv6), `AF_UNIX` (локальные). Типы: `SOCK_STREAM` (TCP), `SOCK_DGRAM` (UDP), `SOCK_RAW`.

**14. Что произойдёт, если не обнулить структуру `sockaddr_in` через `memset()`?**  
В поле `sin_zero[8]` останется «мусор» со стека. Ядро может отвергнуть адрес или вести себя непредсказуемо. В C++ решается инициализацией `sockaddr_in addr{}`.

**15. Почему нужно закрывать сокет через `close()`?**  
Освобождает FD в таблице процесса, буферы ядра и (для сервера) локальный порт. Иначе — утечка дескрипторов, в пределе — ошибка `EMFILE`.
